# MLS / encryption audit — 2026-08-28

Status: audit complete, fixes NOT yet implemented. Findings ranked; each item says
exactly where to patch. Companion: `.vibe/memory.md` (2026-08-28 entries).

## Verdict

The MLS core is sound: OpenMLS 0.8.1, pinned ciphersuite, KeyPackages validated before
trust (`core/vibe_secure/src/trust.rs`, `session.rs::add_members`), panic guards with
session poisoning, bucket padding, TOFU pinning of the peer signature key
(`ios/Sources/Core/VibeSecureTrust.swift`), server ignores body `senderUserId` and
returns 404 for both not-found and not-allowed (`server/lib/vibe_web/controllers/mls_controller.ex`).

The holes are all *around* MLS: the legacy hybrid path, the missing manual verification
surface, and secrets at rest.

## Gaps and where to patch

### 1. Silent downgrade to hybrid + unpinned RSA keys (HIGH)
- Trigger: `VibeSecureEstablishment.establishDirectMessage` (`ios/Sources/Core/VibeSecureEstablishment.swift:229-247`)
  treats a missing KeyPackage as `markPeerKeysUnavailable` + `finish(true)`; `ChatEngine.sendMessage`
  (`ios/ChatModule/ChatEngine.swift`, grep `peerKeysUnavailable`) then seals the hybrid envelope.
- Hybrid = per-message AES-256-GCM key wrapped under a static RSA-2048-OAEP key
  (`ChatEngine.swift` `chatEngineRSAEncryptOAEP`, key from `/api/user/:id/prekey-bundle`).
  No forward secrecy, no sender signature, and the RSA public key is **not pinned** —
  a hostile server can answer "no KeyPackage" and substitute the RSA key: full MITM on any
  DM that was never MLS-confirmed.
- Patch: (a) pin the peer RSA public key on first contact next to `VibeSecureTrust`
  (same evaluate/acceptChange shape); (b) for DMs never `isPeerConfirmed`, keep the message
  queued with a visible "waiting for peer keys" state instead of sealing hybrid. Established
  chats already never downgrade (`isPeerConfirmed` gate in `sendMessage`).

### 2. Safety number has no UI (HIGH)
- Exists: `vibe_safety_number` (Rust) → `VibeSecureSessions.safetyNumber(peerUserId:)`
  (`ios/Sources/Core/VibeSecureSessions.swift:401`). No caller outside Core.
- Patch: chat-info/profile row "Verify encryption" showing 60 digits in 12×5 groups, and an
  "Accept new identity" action calling `VibeSecureTrust.acceptChange` when
  `verifyPeer` returns `.identityChanged` (`VibeSecureEstablishment.swift:322-341`).

### 3. MLS secrets plaintext at rest (MEDIUM)
- `core/vibe_secure/src/provider.rs`: `openmls_sqlite_storage` with JSON codec stores signature
  private keys, HPKE keys and epoch secrets in plain SQLite; only OS file protection applies.
  The core store is Keychain-sealed (`VibeCoreStoreKey`); the MLS DB is not.
- Patch: SQLCipher for the MLS connection keyed by `VibeCoreStoreKey.loadOrCreate()`, or an
  app-level sealed codec. Migration must be fail-closed like `VibeSecureProvider::open`.

### 4. Retained plaintext never forgotten (MEDIUM)
- `VibeSecureSessions` retention store (`retained.v1`, sealed) keeps plaintext for deleted and
  view-once messages until LRU eviction.
- Patch: add `forget(messageId:)` removing `store/alias/order/unrecoverable` entries and
  persisting via `persistRetentionLocked`; call it from the delete and view-once tombstone
  paths in `ChatEngine` (grep `tombstone`, `deleteMessage`).

### 5. Android pushPreview plaintext (MEDIUM)
- `android/app/.../chat/ChatEngine.kt:1804-1834` and `android/chat-module/.../ChatEngine.kt:1583`
  put `pushPreview` (trimmed plaintext) in the wire payload. iOS no longer does.
- Patch: drop the field; server push falls back to a generic preview.
